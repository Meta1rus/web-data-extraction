## 1. Базовые понятия: что такое парсинг веб-страниц?

### Чем парсинг (Scraping) отличается от API?
* **API:** Сайт сам добровольно отдаёт структурированные «чистые» данные в формате JSON (как в Лабораторной 1).
* **Парсинг (Web Scraping):** У сайта нет API. Мы загружаем обычную HTML-страницу (ту самую, которую видит пользователь в браузере) и программно «выковыриваем» из неё нужный текст: названия товаров, цены, отзывы и ссылки.

### Что такое HTML и DOM-дерево?
Любая веб-страница состоит из тегов:
```html
<div class="card thumbnail">
  <a class="title" href="/product/31" title="Packard 255 G2">Packard 255...</a>
  <h4 class="price"><span itemprop="price">$416.99</span></h4>
  <div class="ratings">
    <p data-rating="2">2 reviews</p>
  </div>
</div>
```
* **Тег:** `<div>`, `<a>`, `<p>`, `<span>`.
* **Атрибут:** `class="title"`, `href="/product/31"`, `title="..."`.
* **Атрибуты `data-*`:** Специальные пользовательские атрибуты в стандарте HTML5. Разработчики сайтов используют их для хранения служебных данных, например `data-rating="2"`.
* **Текст внутри тега:** `$416.99`.

## 2. Разбор части A: программный парсинг (`scraper.py`)

### Используемые библиотеки:
1. **`requests`** — скачивает HTML-код веб-страницы по URL.
2. **`BeautifulSoup`** (из пакета `bs4`) — разбирает текст HTML в дерево объектов, по которому можно искать элементы с помощью CSS-селекторов.
3. **`pandas`** — библиотека для анализа и обработки табличных данных (очистка, приведение типов, удаление дубликатов, экспорт в CSV).

### Пошаговый разбор ключевых функций:

#### 1. Сеть, таймаут и повторные попытки (`fetch`):
```python
TIMEOUT = 10
RETRIES = 3

def fetch(url: str, params: dict | None = None) -> str:
    last_error: Exception | None = None
    for attempt in range(1, RETRIES + 1):
        try:
            resp = SESSION.get(url, params=params, headers=HEADERS, timeout=TIMEOUT)
            resp.raise_for_status()
            return resp.text
        except (requests.Timeout, requests.ConnectionError, requests.HTTPError) as e:
            last_error = e
            if attempt < RETRIES:
                time.sleep(2 ** (attempt - 1))
    raise RuntimeError(f"Failed to fetch {url} after {RETRIES} attempts") from last_error
```
* **Зачем нужен `timeout=10`?** Если сервер завис или пропал интернет, программа без таймаута может «висеть» бесконечно. С параметром `timeout=10` запрос прервется через 10 секунд с ошибкой `Timeout`.
* **Зачем нужны повторные попытки (Retries)?** В сети часто случаются кратковременные сбои (мигание Wi-Fi, перегрузка сервера). Если запрос упал с первой попытки, мы не завершаем программу аварийно, а пробуем снова (всего 3 попытки: 1 основная + 2 повторные по требованию задания).
* **Экспоненциальная задержка (`2 ** (attempt - 1)`):** перед 2-й попыткой ждём 1 секунду ($2^0$), перед 3-й — 2 секунды ($2^1$). Это стандартная практика в сетевом программировании, чтобы не спамить упавший сервер.

* `BeautifulSoup(html, "html.parser")` создает объект «супа», который понимает структуру документа.
* `soup.select("div.card.thumbnail")` находит **все** карточки товаров на странице. На одной странице их ровно 6 штук.

Внутри карточки мы извлекаем поля:
1. **Название:** `link = card.select_one("a.title")` → берём `link.get("title")`. Почему берем атрибут `title`, а не текст ссылки? Потому что в тексте ссылки длинное название обрезано троеточием (`Packard 255...`), а в атрибуте `title` записано полное имя!
2. **Цена:** `card.select_one("h4.price span[itemprop=price]").get_text()`. Возвращает строку `"$416.99"`.
3. **Рейтинг из `data-*` атрибута:** 
   ```python
   rating = card.select_one("div.ratings p[data-rating]")
   rating.get("data-rating")
   ```
   В задании требовалось найти `data-*` атрибут. В карточке у тега `<p>` есть атрибут `data-rating="2"`. Метод `.get("data-rating")` извлекает это число.
4. **Количество отзывов:** `card.select_one("span[itemprop=reviewCount]").get_text()`. Возвращает `"2"`.
5. **Ссылка и ID:** 
   * `urljoin(BASE_URL, href)` превращает относительную ссылку `/product/31` в полную `https://webscraper.io/test-sites/e-commerce/static/product/31`.
   * Регулярное выражение `re.search(r"/product/(\d+)", href)` вытаскивает из ссылки число `31` — это ID товара.

#### 3. Пагинация (`last_page_number` и `scrape`):
* На сайте внизу есть переключатель страниц: `<ul class="pagination"> <li><a>1</a></li> <li><a>2</a></li> ... </ul>`.
* Функция `last_page_number` считывает максимальную цифру из ссылок (для ноутбуков это 20 страниц).
* Скрипт в цикле проходит по страницам `?page=1`, `?page=2`, ... `?page=20` и собирает все товары.

#### 4. Очистка и приведение типов данных (`clean`):
```python
def clean(rows: list[dict]) -> pd.DataFrame:
    df = pd.DataFrame(rows)
    
    # 1. Очистка пробелов по краям строк
    for col in df.select_dtypes(include="object").columns:
        df[col] = df[col].str.strip()

    # 2. Очистка цен от знака доллара и перевод в float: "$416.99" -> 416.99
    df["price_usd"] = pd.to_numeric(df["price_usd"].str.replace(r"[^\d.]", "", regex=True),
                                    errors="coerce")

    # 3. Приведение целочисленных колонок к типу Int64
    df["rating"] = pd.to_numeric(df["rating"], errors="coerce").astype("Int64")
    df["reviews"] = pd.to_numeric(df["reviews"], errors="coerce").astype("Int64")
    df["product_id"] = pd.to_numeric(df["product_id"], errors="coerce").astype("Int64")

    # 4. Удаление дубликатов
    df = df.drop_duplicates().reset_index(drop=True)
    return df
```
* По заданию требовалось:
  1. Привести числовые поля к числовым типам (`float64` для цен, `Int64` для рейтинга, отзывов и ID).
  2. Удалить дубликаты (`df.drop_duplicates()`).
  3. Посчитать долю пропусков (`df.isna().mean() * 100`, у нас 0.0% во всех колонках).
  4. Сохранить в CSV (`df.to_csv("products.csv")`).

## 3. Разбор части B: No-code парсинг в Octoparse

### Что такое Octoparse?
**Octoparse** — это программа с графическим интерфейсом (GUI). Она запускает встроенный браузер Chromium, в котором пользователь мышкой кликает по элементам страницы, а программа сама строит алгоритм сбора данных.

### Как устроен визуальный сценарий (Workflow)?
В окне Octoparse строится блок-схема:
1. **Start:** Переход по адресу `https://webscraper.io/test-sites/e-commerce/static/computers/laptops`.
2. **Pagination (Пагинация):** Цикл, который кликает по кнопке следующей страницы `Next >` внизу сайта и листает страницы с 1 по 20.
3. **Loop Item (Цикл по карточкам):** На каждой открытой странице программа находит повторяющийся блок карточки товара.
4. **Extract Data (Извлечение):** Из каждой карточки вытаскиваются поля:
   * Название (текст ссылки `a.title`);
   * Цена (текст `$416.99`);
   * Отзывы (текст `2 reviews`);
   * Рейтинг (атрибут `data-rating`);
   * Ссылка (атрибут `href`);
   * Описание (текст `p.description`).
5. **Run & Export:** Запуск на компьютере и выгрузка результата в файл `octoparse_products.csv` (117 строк).

## 4. Сравнение подходов (Главная таблица для отчёта)

| Критерий | BeautifulSoup (Python) | Octoparse (No-Code) |
|---|---|---|
| **Порог входа** | Требуются знания Python, HTML и регулярных выражений | Достаточно уметь кликать мышкой по экрану |
| **Типы данных** | Полный контроль: в коде мы сами превратили `$416.99` в число `416.99 (float)` | Всё выгружается как сырой текст со знаком `$` |
| **Скорость сбора** | Очень высокая: качает только HTML без рендеринга стилей, картинок и рекламы | Медленнее: открывает страницу в полноценном браузере со всеми ресурсами |
| **Обработка данных** | Автоматическая (дедупликация, фильтрация, проверка на NaN прямо на лету) | Требует ручной постобработки в Excel после экспорта |
| **Гибкость** | Любая логика (повторные попытки, прокси, сохранение в SQL/PostgreSQL) | Ограничено функциями интерфейса программы |

## 5. Возможные вопросы на защите и как на них отвечать

**В: Что такое CSS-селектор и какие селекторы вы использовали?**  
**О:** *CSS-селектор — это шаблон для поиска элементов в разметке HTML. Например:*
* `div.card.thumbnail` — тег `div`, у которого одновременно есть классы `card` и `thumbnail` (карточка товара);
* `a.title` — ссылка с классом `title`;
* `span[itemprop=price]` — элемент `span`, имеющий атрибут `itemprop` со значением `price` (микроразметка цены).

**В: Где в вашей странице находился `data-*` атрибут по заданию?**  
**О:** *В блоке рейтинга товара: `<p data-rating="2">`. Значение рейтинга (от 1 до 5) хранится в атрибуте `data-rating`, откуда мы его и извлекли методом `rating.get("data-rating")`.*

**В: Зачем очищать данные через `pd.to_numeric` и убирать знаки доллара?**  
**О:** *С сайта цена приходит как строка `"$416.99"`. Со строками нельзя производить математические операции (считать среднее, строить графики, фильтровать «дешевле 500»). Регулярным выражением мы удаляем знаки валюты и приводим поле к вещественному числу `float64`.*

**В: Как реализована защита от сетевых сбоев в коде?**  
**О:** *В функции `fetch` задан `timeout=10` секунд на запрос и цикл из 3 попыток. Если возникает сетевая ошибка или таймаут, программа делает паузу (1, затем 2 секунды) и пробует выполнить запрос повторно.*
