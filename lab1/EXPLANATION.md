## 1. Базовые понятия: что такое API и как это работает

### Что такое API простыми словами?
Обычно, когда вы открываете сайт в браузере (например, `github.com`), сервер возвращает вам **HTML-код** (красивую разметку с картинками, кнопками и стилями), предназначенную для глаз человека.

Но программам не нужны кнопки и картинки — им нужны **чистые данные**. 
**API (Application Programming Interface)** — это специальный интерфейс сайта, созданный для программ. Вместо веб-страницы сервер API возвращает структурированные данные (обычно в формате **JSON**).

### Что такое HTTP-запрос?
Вся работа в сети построена на схеме **«Клиент отправляет запрос → Сервер возвращает ответ»**:
* **Метод запроса:** Самый частый — `GET` (получить данные).
* **URL (эндпоинт):** Адрес конкретной функции на сервере, например `https://api.github.com/users/Meta1rus/repos`.
* **Заголовки (Headers):** Служебная информация о клиенте (в каком формате ждём ответ, кто мы такие, наш токен авторизации).
* **Параметры строки запроса (Query Params):** Дополнительные фильтры после знака `?`, например `?page=1&per_page=100`.
* **Код ответа (Status Code):**
  * `200 OK` — всё успешно;
  * `403 Forbidden` — доступ запрещён (например, нет ключа или кончился лимит);
  * `404 Not Found` — пользователь или ресурс не найден.

### Что такое JSON?
**JSON (JavaScript Object Notation)** — текстовый формат хранения данных. В Python он превращается в обычные словари (`dict`) и списки (`list`):
```json
{
  "name": "tinder-for-programmers",
  "stargazers_count": 0,
  "owner": {
    "login": "Meta1rus"
  }
}
```

## 2. Разбор скрипта 1: `github_repos.py`

### Какую задачу решает скрипт?
Подключается к серверу GitHub и выгружает список всех публичных репозиториев указанного пользователя в JSON-файл.

### Полный код с построчным объяснением:

```python
import json       # Библиотека для работы с форматом JSON (сохранение в файл)
import os         # Библиотека для чтения переменных окружения (например, токена)
import sys        # Для чтения аргументов командной строки (sys.argv)

import requests   # Главная библиотека Python для отправки HTTP-запросов

API_URL = "https://api.github.com/users/{username}/repos"
```

#### Функция `get_user_repos(username, token)`:
```python
def get_user_repos(username: str, token: str | None = None) -> list[dict]:
    session = requests.Session()
    session.trust_env = False
```
* `requests.Session()` создает постоянную сессию для отправки запросов (это быстрее, чем каждый раз открывать новое соединение).
* `session.trust_env = False` отключает влияние системных сетевых прокси, если на компьютере включен или некорректно выключен VPN.

```python
    headers = {
        "Accept": "application/vnd.github+json",
        "X-GitHub-Api-Version": "2022-11-28",
    }
    if token:
        headers["Authorization"] = f"Bearer {token}"
```
* В `headers` мы говорим GitHub: «Пожалуйста, верни ответ в формате GitHub JSON версии API от 28 ноября 2022 года».
* Если передан `token`, мы прикрепляем его в заголовок `Authorization: Bearer <токен>`. Без токена GitHub разрешает делать только 60 запросов в час, а с токеном — 5000.

#### Как работает пагинация (постраничный обход)?
```python
    repos = []
    page = 1
    while True:
        resp = session.get(
            API_URL.format(username=username),
            headers=headers,
            params={"per_page": 100, "page": page, "sort": "updated"},
            timeout=10,
        )
        resp.raise_for_status()
        chunk = resp.json()
        if not chunk:
            break
        repos.extend(chunk)
        page += 1
    return repos
```
* **Почему нельзя получить всё сразу одной строкой?** Если у пользователя 500 репозиториев, сервер не отдаст их одним куском, чтобы не перегружать память. GitHub отдаёт максимум 100 штук за раз (`per_page: 100`).
* Поэтому мы запускаем бесконечный цикл `while True`:
  1. Запрашиваем страницу 1 (`page=1`).
  2. `resp.raise_for_status()` проверяет: если сервер вернул ошибку (например 404), программа остановится и сообщит об этом.
  3. `chunk = resp.json()` превращает текст ответа в список словарей Python.
  4. `if not chunk: break` — если вернулся пустой список `[]`, значит репозитории закончились, и цикл останавливается.
  5. `repos.extend(chunk)` добавляет полученные 100 репозиториев в общий список.
  6. Увеличиваем номер страницы `page += 1` и повторяем.

#### Функция `main()`:
```python
def main() -> None:
    username = sys.argv[1] if len(sys.argv) > 1 else "Meta1rus"
    token = os.getenv("GITHUB_TOKEN")

    repos = get_user_repos(username, token)

    out_file = f"{username}_repos.json"
    with open(out_file, "w", encoding="utf-8") as f:
        json.dump(repos, f, ensure_ascii=False, indent=2)
```
* `sys.argv[1]` позволяет запустить скрипт для любого пользователя: `python3 github_repos.py octocat`. Если аргумент не передан, берётся `Meta1rus`.
* `json.dump(..., indent=2)` записывает полученные данные в файл с красивыми отступами в 2 пробела, чтобы человеку было удобно читать.
* Далее в цикле выводится краткая сводная таблица в терминал.

## 3. Разбор скрипта 2: `api_auth_request.py` (NASA API)

### Какую задачу решает скрипт?
1. Показать, что выбранное API действительно требует авторизацию (при запросе без ключа сервер вернёт ошибку 403).
2. Выполнить успешный запрос, передав секретный API-ключ.
3. Сохранить полученные данные в JSON.

### Почему выбрано NASA API?
В исходном задании предлагалось искать API в каталоге `programmableweb.com`. Однако этот сайт окончательно закрылся в 2023 году. Поэтому мы взяли официальный открытый каталог `public-apis` и выбрали NASA Open APIs (`api.nasa.gov`).

### Тип авторизации: API Key в Query-параметрах
Бывают разные типы авторизации:
* **API Key в query-параметрах** (как у NASA): ключ передается прямо в строке адреса: `https://api.nasa.gov/planetary/apod?api_key=ВАШ_КЛЮЧ`.
* **Bearer Token в Headers** (как у GitHub): передается скрыто в заголовках.
* **Basic Auth**: логин и пароль в заголовке `Authorization: Basic ...`.

### Разбор кода:
```python
BASE_URL = "https://api.nasa.gov"
API_KEY = os.getenv("NASA_API_KEY", "hmtYnLTLanrRLFnolKLnqISkaoZCIhus1j6ziJgv")
```
Ключ можно передать через переменную окружения, либо по умолчанию используется ваш личный ключ NASA.

```python
def request(endpoint: str, params: dict, with_auth: bool) -> requests.Response:
    params = dict(params)
    if with_auth:
        params["api_key"] = API_KEY
    resp = SESSION.get(f"{BASE_URL}{endpoint}", params=params, timeout=15)
    print(f"GET {resp.url.replace(API_KEY, '***')}")
    print(f"  HTTP {resp.status_code}; остаток лимита: "
          f"{resp.headers.get('X-RateLimit-Remaining', 'n/a')}")
    return resp
```
* `with_auth=True/False`: переключатель — подставлять ключ в запрос или нет.
* `resp.url.replace(API_KEY, '***')`: чтобы не светить реальный ключ в консоли терминала, мы заменяем его на звездочки.
* `resp.headers.get('X-RateLimit-Remaining')`: сервер NASA в служебных заголовках сообщает, сколько запросов у вас еще осталось до исчерпания лимита.

#### Что происходит в `main()`:
1. **Запрос 1 (без ключа):**
   Делаем запрос к `https://api.nasa.gov/planetary/apod`. Сервер видит, что ключа нет, и отвечает `403 Forbidden` с телом `{"error": {"code": "API_KEY_MISSING"}}`. Мы сохраняем это в `nasa_apod_no_auth.json`. Это железное доказательство для преподавателя, что API защищено.
2. **Запрос 2 (с ключом к APOD):**
   Передаем `api_key`. Сервер отвечает `200 OK` и возвращает информацию об астрономической картинке дня. Сохраняем в `nasa_apod_response.json`.
3. **Запрос 3 (с ключом к NeoWs):**
   Запрашиваем список околоземных астероидов за определенную дату. Сервер отвечает `200 OK` и возвращает данные по 5 астероидам. Сохраняем в `nasa_neo_response.json`.

## 4. Возможные вопросы на защите и как на них отвечать

**В: Зачем в коде GitHub используется цикл `while True`, а не один вызов `get`?**  
**О:** *Потому что GitHub использует постраничную пагинацию. За один запрос сервер возвращает не более 100 записей. Цикл запрашивает страницу за страницей (`page=1, 2, ...`) до тех пор, пока сервер не вернет пустой список.*

**В: Каким способом передается авторизация в NASA API, а каким — в GitHub?**  
**О:** *В NASA API авторизация реализована через API-ключ в query-параметрах URL (`?api_key=...`). В GitHub авторизация (если задана) передается в HTTP-заголовке `Authorization: Bearer <token>`.*

**В: Что вернет NASA API, если не передать ключ?**  
**О:** *Сервер вернет статус `403 Forbidden` с сообщением `API_KEY_MISSING`. Это зафиксировано в файле `nasa_apod_no_auth.json`.*

**В: Что такое `resp.raise_for_status()`?**  
**О:** *Это метод библиотеки `requests`, который автоматически выбрасывает исключение `HTTPError`, если статус ответа означает ошибку (коды 4xx или 5xx). Это страхует программу от работы с некорректным ответом.*
