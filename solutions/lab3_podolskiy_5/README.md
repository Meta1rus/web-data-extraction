# Лабораторная 3 — сбор данных через REST API: код и no-code

**Студент:** Подольский Ф. А., ПМИ-3-2025. **Вариант 5 — CoinGecko.**

**Источник:** CoinGecko API v3, `https://api.coingecko.com/api/v3` (keyless или бесплатный Demo-ключ).
Основной эндпоинт — `GET /coins/markets` (постраничная пагинация `per_page`/`page`, жёсткий лимит частоты),
обогащение — `GET /coins/{id}/market_chart` (30-дневная история цены, капитализации и объёма).
**Задача:** капитализация и суточная волатильность топ-активов. Данные — *Powered by CoinGecko*.

## Запуск (macOS)

```bash
cd lab3_podolskiy_5
cp .env.example .env      # необязательно: вписать COINGECKO_DEMO_API_KEY
./run_real.sh             # venv + зависимости + исполнение lab3.ipynb с сохранением выводов
```

`run_real.sh` создаёт `.venv` (если его нет), ставит `requirements.txt`, регистрирует ядро Jupyter внутри `.venv`,
исполняет блокнот сверху вниз (`jupyter nbconvert --execute --inplace`) и печатает сводку; полный вывод — в
`logs/real_run_<время>.log`. Ключ `--fresh` переносит прошлые результаты в `logs/backup_<время>/` и начинает с нуля.

Ожидаемое время исполнения блокнота: **≈10 минут без ключа** (пауза 6,5 с между запросами, всего ≈90 запросов
вместе с пробами и демонстрацией 429), **≈4 минуты с Demo-ключом** (пауза 2,5 с), плюс 1–2 минуты на установку пакетов
при первом запуске. Итоговый прогон 16.10.2026 без ключа занял **18 мин** (1094 с): три ответа 429 с
`Retry-After: 60` добавили 3 минуты ожидания.

Вручную (VS Code / Jupyter):
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# открыть lab3.ipynb, выбрать ядро .venv, Run All
```

No-code часть запускается в n8n; импорт, запуск и результат — в [nocode/INSTRUCTIONS.md](nocode/INSTRUCTIONS.md).

## Как устроен сбор

| Шаг | Реализация |
|---|---|
| Сессия | `requests.Session`: `User-Agent: PSU-edu-crawler/1.0 (+https://github.com/Meta1rus/web-data-extraction; student lab)`, `Accept: application/json`, `timeout=(5, 30)` в каждом запросе |
| Разбор ответа | `parse_json`: статус → `Content-Type` → JSON; любая ошибка содержит код, URL и первые 200 байт тела |
| Пагинация | `fetch_markets`: `per_page=100`, `max_records=400`, `max_pages=5`; номер страницы = `received // per_page + 1` (по фактически полученному); стоп — пустая/неполная страница, `total` (если придёт), `max_records`, `max_pages`; цикл `for`, не `while True` |
| Скорость | `RateLimiter`: интервал между запросами, после 429 растёт в 1,5 раза |
| Повторы | `request_json`: только 429, 500/502/503/504 и сетевые сбои; `Retry-After` (секунды или HTTP-дата), иначе экспонента 3·2ⁿ с с «равным» джиттером; не больше 6 попыток; прочие 4xx — сразу исключение |
| Журнал | каждая HTTP-попытка → `collection_log.csv`: время UTC, прогон, этап, страница, URL, параметры, попытка, код, число записей, длительность, `Retry-After`, пауза, примечание |
| Нормализация | `json_normalize(sep="_")` (объект `roi` → `roi_times`, `roi_currency`, `roi_percentage`); `json_normalize(record_path=["sparkline_in_7d", "price"], meta=["id"])` — 168 почасовых цен на монету → σ за 7 дней |
| Обогащение | `/market_chart?days=30&interval=daily` для новых монет топ-50 → σ дневных лог-доходностей, Δ капитализации за 30 дней, средний объём; `merge(validate="one_to_one")` с проверкой числа строк |
| Качество | полнота полей, дубликаты по (`id`, `snapshot_date`), типы (даты UTC, числа), правила R1–R7 → `qc_flags` |
| Инкрементальность | водяной знак в `state.json` (дата снимка + id монет); повторный запуск в тот же день → 0 новых строк и 0 запросов обогащения |
| Условные запросы (бонус) | `ETag` страниц хранится в `state.json`, при повторе — `If-None-Match`; ответ 304 → записи из `data_raw.jsonl` |
| 429 | этап 10: серия ≤ 25 быстрых запросов без ограничителя до первого 429 и успешного повтора; если 429 не случился — явное сообщение и та же логика на имитации (`ScriptedAdapter`) |

## Соответствие требованиям

| Требование задания | Где / как выполнено |
|---|---|

| повторы только 429/5xx, экспонента с джиттером, Retry-After, ограниченное число попыток, без повторов на 4xx | этап 2, `request_json`, `backoff_delay`, `parse_retry_after`; проверка 404 без повторов — ячейка «Проверка клиента»; все ветки — на имитации в этапе 10 |

| инкрементальность: `state.json`, водяной знак, второй прогон — 0 новых | этапы 5 и 9, `select_new`, `run_pipeline`; сводка двух прогонов печатается рядом |
| секреты только через env/.env, маскированные | `COINGECKO_DEMO_API_KEY` из окружения / `.env` (в `.gitignore`), `mask()`; ключ только в заголовке, в журнал не попадает |

| n8n: расписание, HTTP Request с параметрами, разворачивание массива, ≥ 3 преобразования, CSV, ветка ошибки, пагинация | `nocode/workflow.json`: Schedule Trigger; HTTP Request с query-параметрами, заголовками, Retry On Fail и ошибочным выходом; пагинация — Loop Over Items + Wait; Split Out массива `body`; Edit Fields — переименование, типы, вычисляемые поля; Convert to File (CSV); ветка ошибки → Stop and Error. | таблица сравнения Python vs n8n + вывод о гибриде | `report.md`, раздел 7; измеренные значения печатает этап 12 |
| паспорт API | блокнот (после этапа 1) и `report.md`, раздел 2 |

паузы — ограничитель скорости и пауза в пробах.

## Проверка на локальной имитации

Помимо реального прогона, код проверялся на локальной имитации API (`http.server` на 127.0.0.1: те же пути и поля, что
у CoinGecko, токен-бакет с 429, разовый 503 на 3-й странице, дубликат на границе страниц, `ETag`/304, пропуски
`max_supply`/`roi`); адрес имитации подставляется через `COINGECKO_BASE_URL`. Блокнот исполнялся целиком дважды подряд
в одной папке (Python 3.13 + pandas 3.0 и Python 3.11 + pandas 2.1): падений и предупреждений нет; 400 записей /
4 страницы; дубликат на границе страниц удалён (400 → 399); 429 и 503 в основном сборе обработаны повтором; повторный
прогон — 0 новых строк и 0 запросов обогащения (при повторе в ту же минуту — 304 на всех страницах). Цифры имитации
в отчёт не переносятся. Workflow n8n проверен в n8n 2.43.6 (Node.js 24) на той же имитации: 3 страницы → 299 строк CSV,
сбой 503 снят повтором, ветка ошибки срабатывает на 404 (подробности — `report.md`, раздел 6). Для n8n нужен Node.js 24+.
Реальный запуск 16.10.2026 (n8n 2.35.7): 300 строк, 22,7–28,5 с, один сетевой сбой снят повтором.

## Что показал реальный прогон

- Набор полей `/coins/markets` и формат `/market_chart` совпали с документацией CoinGecko: пробы этапа 1 вернули все
  ожидаемые поля, пропуски есть только там, где их нет в самом источнике (`report.md`, раздел 5).
- `ETag`, `total` и `per-page` приходят с каждым ответом 200, `Retry-After: 60` — с каждым 429, заголовков
  `X-RateLimit-*` нет.
- Лимит keyless-доступа плавающий: в основном сборе было два ответа 429 (страница 4 и одна монета при обогащении),
  оба сняты паузой по `Retry-After`; прогон занял 18 мин вместо ожидаемых 10. С Demo-ключом сбор быстрее (пауза 2,5 с).
- В демонстрации 429 без ключа ответ 429 пришёл уже на втором запросе. С Demo-ключом лимит (30–100/мин) может не
  исчерпаться за 25 запросов — тогда блокнот сообщает об этом, а реакция на 429 показывается на имитации.
