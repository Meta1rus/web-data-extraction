## 1. Цель и вариант

Цель — промышленный краулер на Scrapy с двухуровневым обходом, четырёхзвенным Item Pipeline и вежливыми
настройками, эквивалентный конвейер в n8n на подмножестве и обоснованный выбор инструмента.

Вариант 5: `scrapingcourse.com/ecommerce`; уровень 1 — пагинация каталога; уровень 2 — карточка товара
(название, цена, артикул, категории, описание, изображение). Требования к объёму: ≥ 300 записей, ≥ 10 страниц.

**Ограничение источника.** На 15.10.2026 `https://www.scrapingcourse.com/robots.txt` содержит
`User-agent: *` / `Disallow: /ecommerce/*` — запрещён весь каталог. При обязательном `ROBOTSTXT_OBEY = True`
паук делает 1 запрос (robots.txt) и отсекает стартовую страницу (`robotstxt/forbidden = 1`, 0 записей).
Кроме того, каталог занимает 12 страниц по 16 товаров (≤ 192 SKU) — меньше 300 записей. Предложена замена
по согласованию с преподавателем на учебный магазин того же автора `scrapeme.live/shop` (WooCommerce, 755
товаров, 48 страниц, `/shop/` разрешён robots.txt); код не меняется, меняется `START_URL`.
Согласование: ⟪ЗАПОЛНИТЬ: дата и ответ преподавателя⟫. Источник итогового прогона: ⟪ЗАПОЛНИТЬ⟫.

## 2. Карта источника

| Уровень | Точка входа | Данные | Переход |
|---|---|---|---|
| 1 — каталог | `/ecommerce/` (`/shop/`), далее `/page/N/` | ссылки на карточки; контекст: название и цена в списке, позиция, `data-product_sku`, `data-product_id` | `nav.woocommerce-pagination a.next` |
| 2 — карточка | `/ecommerce/product/<slug>/` | название, цена (скидка, диапазон), SKU, категории, метки, краткое и полное описание, изображение | — |

Ключ уникальности — артикул (SKU). URL не подходит: один товар может публиковаться под двумя адресами
(такой случай есть в тестовых данных имитации и отсекается звеном 300).

## 3. Архитектура решения

| Компонент Scrapy | Задача в проекте |
|---|---|
| Spider `ecommerce` (`spiders/ecommerce.py`) | стартовый запрос, разбор каталога и карточек, `cb_kwargs`, `errback`, `closed()` → `stats_<N>.json` |
| Scheduler + dupefilter | очередь, приоритет карточек (`priority=10`) над следующей страницей, отсев повторных URL; с `JOBDIR` — на диске |
| Downloader middleware (штатные) | RobotsTxt (Protego), UserAgent, DownloadTimeout, Retry, HttpCompression (gzip), HttpCache (отладка) |
| Extensions | AutoThrottle, CloseSpider (`CLOSESPIDER_*`), CoreStats, LogStats |
| Item (`items.py`) | схема `ProductItem`: сырые поля, вычисляемые поля, контекст первого уровня |
| Item Pipeline (`pipelines.py`) | 100 валидация → 200 очистка/типизация → 300 дедупликация по SKU → 400 SQLite |
| Feed Exports | `data/items.jsonl` |

## 4. Паук; Spider или CrawlSpider

Выбран `scrapy.Spider`. Обход линейный (каталог → карточки → следующая страница), а правила `CrawlSpider` дают
меньше контроля: нужно передавать в карточку контекст списка через `cb_kwargs`, назначать приоритеты, прерывать
пагинацию аргументом `max_pages`, вешать `errback` на каждый запрос. Пагинация — `response.follow` по ссылке
«следующая», а не по номерам: это переживает изменение числа страниц.

Селекторы — только семантические классы WooCommerce, `data-*`, `itemprop`, `rel`, для каждого поля цепочка
фолбэков (таблица в README), последний рубеж — JSON-LD `Product`. Индексных XPath нет. Пропуски полей не
роняют паука: `.get()` возвращает `None`, решение принимает пайплайн. `errback` различает HTTP-ошибки, таймауты,
DNS, отказ соединения и отсечение robots.txt и пишет каждую в статистику (`errback/<вид>`).

| Настройка | Значение | Обоснование |
|---|---|---|
| `ROBOTSTXT_OBEY` | True | требование курса и площадки; Protego понимает `*` и `$` |
| `USER_AGENT` | `PSU-edu-crawler/1.0 (+https://github.com/Meta1rus/web-data-extraction; student lab)` | учебное назначение и контакт |

| `DOWNLOAD_TIMEOUT` | 20 с | страница — десятки КБ; не держать зависшее соединение |
| `RETRY_TIMES` / `RETRY_HTTP_CODES` | 2 / 408, 429, 500, 502, 503, 504, 522, 524 | только временные сбои |

| `CLOSESPIDER_ITEMCOUNT` | **400** | ≥ 300 + запас на отбраковку (значение итогового прогона) |
| `CLOSESPIDER_PAGECOUNT` / `TIMEOUT` / `ERRORCOUNT` | 700 / 1800 с / 20 | второй рубеж предохранителей |
| `HTTPCACHE_ENABLED` | False (True при отладке, `-s`) | итог — свежие данные; ошибки 4xx/5xx не кэшируются |

## 9. n8n-workflow

`nocode/workflow.json` (22 узла): Schedule Trigger (cron `0 5 * * *`) и Manual Trigger → Set «Параметры»
(`base_url`, `pages = 2`, User-Agent) → Code «Номера страниц» (пагинация циклом по `/page/N/`) → HTTP Request
«Страница каталога» (batching 1 запрос / 1,5 с, таймаут 20 с, Retry On Fail 3 × 3 с, выход ошибки) → HTML Extract
(ссылки карточек) → Split Out → Remove Duplicates (URL) → Loop Over Items (по 4) → HTTP Request «Карточка товара»
(2 параллельно, Retry On Fail) → HTML Extract (9 полей) → Wait 1 с → цикл; по завершении — Remove Duplicates (SKU)
→ Code «Проверка и типизация» → Convert to File (CSV) → Read/Write Files from Disk. Ветка ошибки: выходы ошибок
HTTP-узлов → Set → Code (текст) → дозапись `n8n_errors.log` + Telegram (отключён до настройки бота).

Проверено в n8n 2.43.6 (CLI) на имитации: 30 записей, 34 запроса, 18,9 с; ветка ошибки на закрытом порту —
строка в журнале, выполнение завершено без падения (на локальной имитации).
Реальный запуск: ⟪ЗАПОЛНИТЬ: записей, длительность из Executions⟫; скриншоты — `nocode/screenshot_*.png`.

* **(а) разовый обход 500 страниц** — Scrapy: готовый паук, кэш для отладки, статистика прогона;

## 11. Риски поломки при редизайне и smoke-check

| Риск | Проявление | Защита |
|---|---|---|
| смена темы/классов WooCommerce | 0 карточек на странице, пустые поля | фолбэки селекторов, JSON-LD; `pages/list_without_cards`, `quality/empty/*` |
| смена пагинации | обход 1 страницы | фолбэки `a.next.page-numbers`, `link[rel=next]`; падение числа записей |
| смена формата цены (валюта, «от … до …») | `dropped/bad_price` | разбор диапазонов и валюты; счётчик |
| SKU перестал выводиться | `dropped/missing_fields/sku` | фолбэк на JSON-LD и `data-product_sku` из списка |
| мягкая блокировка/заглушка с кодом 200 | меньше карточек, пустые поля | smoke-check |

`quality/smoke_check.py` сравнивает текущий прогон (метка `main`) с предыдущим по файлам статистики:
предупреждение, если записей меньше на > 20 % или доля пустых значений любого обязательного поля варианта
> 5 % (по счётчикам пайплайна и, дополнительно, по записям текущего прогона в БД); код возврата 1 — удобно
для cron и n8n. Режим `--self-test` подставляет синтетический прогон (−30 % записей, 8 % пустых описаний)
и проверяет, что тревога срабатывает (на имитации — сработала по обоим условиям).

## 12. Правовая и этическая оценка

* **robots.txt.** Соблюдается всегда (`ROBOTSTXT_OBEY = True`, парсер Protego). Источник варианта закрыт
  правилом `Disallow: /ecommerce/*` — сбор не производится, доказательство в журнале; замена — только по
  согласованию. `urllib.robotparser` в Python ≤ 3.12 не понимает шаблоны и на это правило ответил бы «можно» —
  поэтому предварительная проверка использует тот же парсер, что и Scrapy.
* **Нагрузка.** ≤ 2 одновременных запроса к домену, пауза 0,5 с с джиттером, AutoThrottle, предохранители
  `CLOSESPIDER_*`, кэш при отладке; честный User-Agent с контактом. n8n: 1 запрос / 1,5 с к каталогу,
  ≤ 2 параллельно к карточкам и пауза 1 с между батчами; robots.txt n8n сам не проверяет — источник
  проверяется до запуска.
* **Персональные данные.** Каталог учебного магазина: товары, цены, описания, ссылки на изображения.
  Данных о физических лицах нет, 152-ФЗ к собранным данным не применяется; при появлении ПДн (например,
  авторы отзывов) они не сохраняются.
* **Обход защит** не применяется: нет прокси, ротации User-Agent, решения капчи, авторизации.
* **Хранение.** Локально (`data/crawl.db`), до зачёта, без публикации.
