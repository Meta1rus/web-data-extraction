# No-code (n8n): что реализовано, что нет, сколько стоит

## Механизм устойчивости → код → no-code

| Механизм | Реализация в коде (`src/`) | Реализация в n8n (`workflow.json`) | Что реализовать не удалось / ограничения |
|---|---|---|---|
| Ограничение скорости | token bucket на домен 2 запр/с, всплеск 2, джиттер 25 %, Crawl-delay в приоритете | batching HTTP Request (1 запрос / 2 с для каталога, 2 параллельно с интервалом 1 с для карточек) + Wait 2 с между батчами Loop Over Items | нет джиттера и всплесков: интервалы фиксированные; нет учёта Crawl-delay из robots.txt (robots.txt n8n не читает вовсе) |
| Адаптивная задержка | `AdaptiveDelay` по латентности + удвоение при 429/503; AutoThrottle | нет | обратной связи по латентности в узлах нет; можно лишь вручную увеличить Wait |
| Повторы | классы ошибок, full jitter, cap, 4 попытки, бюджет 90 с, Retry-After в приоритете, 4xx не повторяем | Retry On Fail: 4 попытки, 5 с между ними | фиксированная пауза (не экспонента, без джиттера); Retry-After игнорируется; повторяется ЛЮБАЯ ошибка, включая 404/403 — противоречит политике (−10 в коде) |
| Предохранитель (circuit breaker) | `breaker.py`: closed → open → half-open по доменам, изоляция доменов | частичный аналог: после исчерпания повторов на каталоге — Stop and Error, выполнение прекращается, Error Workflow уведомляет | нет состояния между запросами и запусками, нет half-open; «размыкается» весь workflow, а не домен |
| Условные запросы (ETag/Last-Modified) | `ConditionalRequestMiddleware`, `state/etags.json`, ответы 304 | не реализовано | технически возможно: Code с `$getWorkflowStaticData('global')` хранит ETag, HTTP Request шлёт `If-None-Match`, «Never Error» пропускает 304. Но staticData сохраняется только в активированном (не ручном) запуске — проверить вручную нельзя; сложность выше, чем польза на 32 карточках |
| Сжатие | gzip в режиме C (−70,9 % трафика на имитации) | заголовок `Accept-Encoding: gzip` | эффект не измеряется: n8n не показывает объём трафика |
| Инкрементальность | «водяной знак» `state/watermark.json` + 304 каталога | Remove Duplicates → «Remove Items Processed in Previous Executions» по ключу «URL\|цена» | хранится только факт «видели», без времени проверки — нет периодической перепроверки неизменившихся карточек |
| Детектор блокировок | код + маркеры + размер + ожидаемые элементы, артефакты, история прогонов | Code «Проверка содержимого» (маркеры, размер) + IF (карточек ≥ 30, заглушек нет) → Stop and Error | нет сохранения артефактов (тела ответа) и сравнения с медианой прошлых запусков |
| Распределённый лимит (4 процесса) | `SharedTokenBucket` (файл + `fcntl.flock`): 2,0 запр/с суммарно против 8,85 у локальных ведер (на локальной имитации) | нет | параллельные выполнения n8n (queue mode, несколько воркеров) общего лимита на домен не имеют; решение — одно выполнение по расписанию (`concurrency = 1`) или внешний лимитер |
| Наблюдаемость | JSON-журнал каждой попытки, отчёт с 8 порогами | журнал выполнений по узлам (Executions) | нет метрик латентности/кодов в агрегате, нет порогов, кроме IF |
| Оповещения | статус зелёный/жёлтый/красный, коды возврата | Error Trigger → файл / Telegram (узел отключён до настройки бота) | Error Trigger не срабатывает при ручных запусках |
| Расписание | внешний cron / `run_real.sh` | Schedule Trigger `0 5 * * *` | — |

## Оценка стоимости ежедневного сбора

Объём: каталог согласованного источника — 48 страниц × 16 карточек = 768 карточек (по данным площадки — 755 товаров).

| Режим | Запросов в сутки | Выполнений n8n в месяц |
|---|---|---|
| полный обход | 48 + 755 = 803 | 30 (одно выполнение в сутки) |
| инкрементальный (Remove Duplicates) | 48 + изменившиеся карточки (на учебном каталоге ≈ 0) | 30 |
| при разбиении на подпроцессы (Execute Sub-workflow по странице) | те же 803 | 30 × 49 ≈ 1 470 |

* **n8n self-hosted** (`npx n8n`, Docker): лицензия Community бесплатна; расходы — свой компьютер/VPS.
  Ограничение — память на одно выполнение: 803 HTML-страниц в одном выполнении держатся в памяти целиком,
  поэтому полный обход лучше дробить по страницам каталога (что увеличивает число выполнений).
* **n8n Cloud** тарифицирует по числу выполнений workflow (не по узлам и не по запросам): 30–1 470
  выполнений в месяц укладываются в младший платный тариф. Стоимость тарифа на дату сдачи:
  ⟪ЗАПОЛНИТЬ: цена и лимит выполнений с https://n8n.io/pricing⟫.
* **Octoparse** (для сравнения): облачные запуски и ротация IP — в платных планах; при нашем объёме
  достаточно локального запуска на бесплатном плане, но расписание и облако — платные:
  ⟪ЗАПОЛНИТЬ: цена с https://www.octoparse.com/pricing⟫.

Вывод: при таком объёме стоимость определяется не запросами, а способом запуска; главный рычаг экономии —
инкрементальность (−88,9 % запросов на имитации), которая в n8n доступна штатным узлом.
