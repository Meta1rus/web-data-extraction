# No-code компонент: n8n как оркестратор (конфигурация B)

**Что делает n8n:** расписание → запуск пайплайна → проверка отчёта о прогоне → оповещение при жёлтом/красном
статусе → пометка выполнения как сбойного при красном; отдельная ветка — сбой самого workflow.
**Что остаётся в коде:** сбор обоих источников, вежливость и устойчивость, очистка, контракт, UPSERT, метрики качества,
mart. Экспорт — `nocode/workflow.json` (n8n, формат экспорта v1; проверен `json.loads`, все связи ссылаются на
существующие узлы). Как импортировать и какие скриншоты сделать — `nocode/INSTRUCTIONS.md`.

## Узлы workflow

| Узел | Тип | Настройка |
|---|---|---|
| Расписание 03:17 UTC | Schedule Trigger | cron `17 3 * * *`, часовой пояс workflow — UTC |
| Ручной запуск (демо) | Manual Trigger | для показа на защите |
| Параметры запуска | Set | `project_dir`, `python` (`.venv/bin/python`), `args`, `alerts_dir` |
| Запуск пайплайна | Execute Command | `cd "<project_dir>" && .venv/bin/python src/run_pipeline.py --quiet <args>; echo "PIPELINE_EXIT_CODE=$?"`; Retry On Fail 2 попытки / 5 с (только сбой запуска оболочки); On Error → ветка ошибки |
| Разбор RUN_SUMMARY | Code (JS) | последняя строка `RUN_SUMMARY {...}` → `verdict`, `alerts`, `run_id`, `report_path`; код возврата из `PIPELINE_EXIT_CODE` |
| Нужно оповещение? | IF | `verdict ≠ green` ИЛИ `exit_code ≠ 0` |
| Текст оповещения | Set | сообщение: вердикт, прогон, код, список оповещений, путь к отчёту; имя файла оповещения |
| Оповещение → JSON → Записать оповещение | Convert to File + Read/Write Files from Disk | `~/.n8n-files/podolskiy/alert_<время>.json` |
| Telegram | Telegram | **выключен** до добавления учётных данных бота (Retry On Fail 3 / 3 с) |
| Красный статус? → Пометить выполнение как сбой | IF + Stop and Error | красный прогон виден в журнале выполнений n8n как ошибка |
| Сбой запуска команды | Set | ветка ошибки Execute Command (нет python, нет каталога) → то же оповещение |
| При сбое workflow | Error Trigger → Set → Convert → Write | `workflow_error_<время>.json` (Settings → Error workflow → этот workflow) |

## Таблица «этап → код / no-code → что не удалось перенести»

| Этап | В коде | В no-code (n8n) | Перенос |
|---|---|---|---|
| Расписание | cron/launchd (запасной вариант, см. INSTRUCTIONS.md) | Schedule Trigger `17 3 * * *` | **перенесено полностью** |
| Запуск пайплайна | `python src/run_pipeline.py` | Execute Command | перенесено: n8n только запускает |
| Сбор HTML (страницы тем) | requests + BeautifulSoup, 3 стратегии разбора, детектор блокировки | — (возможен HTTP Request + HTML Extract) | **не перенесено**: устойчивые селекторы с фолбэками, точное число звёзд из `aria-label`, сохранение снимков страниц и детектор «200 без карточек» в HTML Extract не выразить |
| Сбор API | водяной знак + ETag (304), режим search без токена | — (возможен HTTP Request с заголовком If-None-Match) | **не перенесено**: хранение ETag и водяного знака между запусками, отбор ключей, учёт квоты по `X-RateLimit-*` потребовали бы внешнего хранилища и Code-узлов — фактически переписывания кода |
| robots.txt | матчер RFC 9309 + сравнение с urllib.robotparser | — | **не перенесено**: в n8n нет проверки robots.txt |
| Повторы | классификация кодов, Retry-After, backoff с джиттером, снижение темпа после 429 | Retry On Fail (фиксированное число попыток и пауза) | частично: n8n не различает 404 и 503, не читает Retry-After |
| Контроль скорости | token bucket на домен + джиттер, Crawl-delay | Wait / размер батча в Loop Over Items | не требуется: n8n не обращается к GitHub |
| Предохранитель | circuit breaker на домен | Stop and Error, ветки ошибок | частично: изоляция отказа одного источника при работе другого — только в коде |
| Очистка и контракт | протокол очистки, pydantic, rejects с причиной | — (Set / Code) | **не перенесено**: строгой типизации и контракта в n8n нет (вывод занятия 6) |
| UPSERT, история | SQLite `ON CONFLICT ... WHERE row_hash ...`, снапшоты | — (Postgres/MySQL Upsert возможен) | не переносилось: SQLite-узла в n8n нет; хэш изменений и синонимы ключей — логика кода |
| Метрики качества | 9 метрик, пороги, вердикт, блокировка mart | IF по вердикту из `RUN_SUMMARY` | частично: вычисление — в коде, реакция — в n8n |
| Отчёт о прогоне | JSON-журнал → `reports/run_report_*.json` | журнал выполнений n8n по узлам | дополняют друг друга |
| Оповещения | список `alerts` в отчёте, код возврата | IF → файл + Telegram; Error Trigger; Stop and Error | **перенесено**: доставка оповещений — сильная сторона n8n |

## Оценка стоимости

| Показатель | Значение |
|---|---|
| Запусков в сутки | 1 (+ ручные демонстрации) |
| Узлов за выполнение | 6–9 (штатный прогон: 5; с оповещением: до 9) |
| HTTP-запросов пайплайна за прогон | полный прогон — 625, ежедневный инкрементальный — 41 (реальный прогон 15.10.2026); запуск из n8n с `--topics web-scraping --max-pages 1` — 3 (16.10.2026) |
| Выполнений в месяц | ≈ 30 |
| Платформа | n8n self-hosted (`npx n8n`) на ноутбуке — бесплатно, без лимита выполнений; облачный тариф не используется |
| Вывод | Оркестрация в n8n оправдана: расписание, журнал выполнений и доставка оповещений «из коробки». Сбор и качество данных в n8n не переносятся без потери свойств (ETag-состояние, водяной знак, robots, контракт) — они остаются в коде, как и рекомендует курс. |

## Реальные запуски из n8n (16.10.2026)

n8n 2.35.7 на Node.js 24.22.0 (Mac автора). Скриншоты — `nocode/screenshots/`, файлы оповещений — `nocode/alerts/`.

| Запуск n8n | Пайплайн | Что произошло | Путь в n8n |
|---|---|---|---|
| № 33, ручной, 37,0 с | `20261016T133543Z`, `--topics web-scraping --max-pages 1`, 11,4 с, 3 HTTP-запроса (robots.txt, 1 страница темы, 1 запрос к API) | вердикт **yellow**: p95 латентности 4,3 с при пороге 3 с (медленная сеть автора); в БД обновлено 213 репозиториев, код 0 | «Нужно оповещение?» → файл `nocode/alerts/alert_20261016_133554.json` → «Красный статус?» = нет → выполнение успешно |
| № 34, ручной, 34,5 с | `20261016T133746Z`, сценарий «Отказ источника» (`GITHUB_API_BASE=https://api.github.invalid`), 33,7 с, 7 запросов | вердикт **red**, код 3: 5 сетевых ошибок к API (71,4 %), предохранитель разомкнулся; HTML-часть собрана (20 карточек) — отказ API изолирован | оповещение → файл `nocode/alerts/alert_20261016_133820.json` → **Stop and Error**, выполнение помечено ошибкой |

Оба пути отработали так, как описано в таблице узлов: жёлтый прогон дал оповещение без пометки ошибки, красный —
оповещение и Stop and Error. n8n при этом сделал только запуск и реакцию; сами 3 и 7 HTTP-запросов выполнил пайплайн.

## Почему не сбор целиком в n8n

Для API это технически возможно (HTTP Request с `If-None-Match`), но состояние ETag и водяного знака n8n между
запусками хранить негде, кроме внешней БД или статических данных workflow (`$getWorkflowStaticData`), которые
сохраняются только у активных workflow по расписанию и не переживают ручные запуски. Для HTML — узел HTML Extract
не даёт фолбэков и проверки «200 без карточек». Поэтому выбрана конфигурация B, а не C.
