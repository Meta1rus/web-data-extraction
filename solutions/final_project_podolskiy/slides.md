## Слайд 1. Вопрос и источники

**Как популярность и активность Python-репозиториев связаны с их тематикой и размером?**

- HTML: страницы тем GitHub `github.com/topics/<topic>?l=python` — 6 тем × 5 страниц × 20 карточек
  (web-scraping, fastapi, machine-learning, data-engineering, cli, telegram)
- API: GitHub REST `/repos/{owner}/{repo}` — звёзды, форки, наблюдатели, issues, размер, даты, лицензия
- Связь: ключ `owner/repo` → 592 репозитория в чистом слое, покрытие связи 100 %
- Конфигурация B: Python собирает и обрабатывает, n8n — расписание, запуск, оповещения

*Комментарий:* почему нужны оба источника (тематика есть только на странице темы, метрики — только в API; звёзды в обоих → проверка парсера).

## Слайд 2. Архитектура и выбор инструментов

Схема: robots.txt → HTML → API (водяной знак + ETag) → raw JSONL → очистка + контракт → SQLite UPSERT → 9 метрик
качества → mart → отчёт о прогоне → n8n (оповещения).

- Диагностика «нужен ли браузер»: requests + BeautifulSoup нашли 20 карточек из 20, текст есть в исходном HTML;
  «Load more…» = обычный GET `page=N+1` → **Playwright не нужен**
- Scrapy не нужен: 30 страниц в сутки по одному домену; лимиты, повторы, возобновление — свои и покрыты тестами
- robots.txt: `/topics/*` разрешено; `/stargazers`, `?tab=`, `?q=` запрещены и не запрашиваются;
  собственный матчер RFC 9309 (urllib.robotparser в Python 3.10–3.12 не понимает `*`)

## Слайд 3. Модель данных и качество

- `repos` (PK `repo_key` = owner/repo, `repo_id` UNIQUE) ← `topic_listings` (PK topic + repo_key), синонимы при
  переименовании, снапшоты по дням, `rejects`, `pipeline_runs`
- Контракт pydantic: формат owner/repo, slug тем, SPDX, UTC-даты, согласованность ключа и дат; rejects с причиной:
  0 записей (0 %)
- 9 метрик со светофором; красный → mart не обновляется (код 2). Текущий вердикт: GREEN (9 из 9 зелёные)
- UPSERT, три прогона (вставлено/обновлено/без изменений): 1) 592/0/0 2) 0/10/582 3) 0/37/555, дублей 0

## Слайд 4. Вежливость, нагрузка, устойчивость

| | Значение |
|---|---|
| Темп | github.com 0,33 запр/с, API 1,5 запр/с, джиттер 30 %, User-Agent с контактом |
| Прогон 1 | 625 запросов, ошибок 0 %, p95 909 мс, 8,1 мин |
| Водяной знак (прогон 2) | запросов к API 10 вместо 592 |
| Условные запросы (прогон 3) | 304: 208 из 224; квоты на 304 израсходовано 0; ETag API нестабилен → If-Modified-Since |
| gzip | страница темы 55 КБ вместо 529 КБ (−89,5 %) |

- 429 → Retry-After / X-RateLimit-Reset → темп домена ×½; 5 отказов подряд → предохранитель; инцидент, код 3
- Обрыв посередине → checkpoint: продолжение без повторных запросов
- Расписание: n8n, ежедневно 03:17 UTC — звёзды меняются в масштабе суток, ≈ 11 % часовой квоты

## Слайд 6. Ограничения и правомерность

- Только топ-100 тем по звёздам (усечение снизу), темы — самоописание авторов, пересечение тем, `size` = размер
  git-истории, звёзды накапливаются; корреляция ≠ причинность; период: 15.10.2026 (один день)
- Правовой чек-лист (12 пунктов): источники из списка курса, robots.txt соблюдён, без авторизации на сайте и обхода
  защиты, ≈ 31 запрос/сутки к github.com, из ПДн — только логин в ключе, mart обезличен (хэш), хранение ≤ 90 дней
